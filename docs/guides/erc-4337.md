# ERC-4337 bundler on a fork: `@condensate/forkit/4337`

`bundler(f)` starts Pimlico's [alto](https://github.com/pimlicolabs/alto) bundler against a fork's anvil, with funded executors. Production code that sends user operations then runs unchanged against real forked state: counterfactual deployment, paymasters, and EIP-7702 accounts.

```ts
import { bundler } from "@condensate/forkit/4337";
import { describeFork, itFork } from "@condensate/forkit/vitest";

describeFork("smart account", { chain: base, blockNumber: 51_900_000n }, (f) => {
  let b: Bundler;
  beforeAll(async () => { b = await bundler(f); });   // before any snapshot (see "Lifecycle")
  afterAll(() => b?.stop());

  itFork("pays out", async () => {
    const account = await toCoinbaseSmartAccount({ client: f.client, owners: [owner], version: "1.1" });
    await f.dealNative(account.address, parseEther("1"));
    const hash = await b.client.sendUserOperation({
      account,
      nonce: await account.getNonce({ key: 0n }),        // see "Deterministic replays"
      calls: [{ to: bob, value: 1n }],
    });
    expect((await b.client.waitForUserOperationReceipt({ hash })).success).toBe(true);
  });
});
```

`b.url` is the bundler's JSON-RPC URL; point your own code or any bundler client at it. `b.client` is a viem bundler client on it that reads through the fork.

## Setup

alto is an **optional peer dependency** and runs as a separate Node.js process:

```sh
bun add -d @pimlico/alto   # or npm/pnpm; forkit needs `node` on PATH to run it
```

forkit resolves `@pimlico/alto` from itself, then from the working directory. `altoBinary` points at another CLI (`…/esm/cli/alto.js`, which runs with Node) or at an alto executable. If alto is missing, `bundler()` throws `AltoNotFoundError` with an install hint.

## Options

| Option | Default | |
|---|---|---|
| `entryPoints` | every canonical EntryPoint (v0.6–v0.9) with code on the fork | versions (`"0.7"`) or addresses; a listed one with no code fails loudly |
| `safeMode` | `false` | alto's ERC-7562 validation rules; turn on to test your account or paymaster passes them |
| `chainType` | `op-stack` for OP-stack chains, `arbitrum` for Arbitrum One/Nova/Sepolia, else `default` | alto's `--chain-type` |
| `executorKeys` | one fixed key (`DEFAULT_EXECUTOR_KEY`) | each funded with 1000 ETH on the fork |
| `utilityKey` | `DEFAULT_UTILITY_KEY` | deploys alto's simulation contract at startup and tops up executors |
| `altoFlags` | — | any other alto flag by its `alto --help` name, e.g. `{ "max-bundle-interval": 200 }`; overrides forkit's |
| `bootTimeoutMs` / `stopTimeoutMs` | 60 000 / 10 000 | |
| `onLog` | dropped (last lines kept for errors) | every line alto prints; `FORKIT_DEBUG=1` prints them and raises alto's log level |

The default keys are public, so only ever use them on a fork.

## Lifecycle

Start the bundler **before any snapshot**: in `beforeAll`, not inside a test. When it starts, alto deploys helper contracts and forkit funds the executors. Reverting to a snapshot taken earlier undoes both. If that happens, the next send fails with an error that says so, rather than hanging.

## Reverts

Per-test snapshot/revert after start is fine. alto normally assumes a chain only moves forward, so forkit makes three adjustments:

- Before each send, forkit mines past the highest block alto has seen. After a revert the chain is lower than that, and alto ignores blocks it thinks it has already processed, so a bundle mined there would never count as included and its executor would stay busy.
- When the block mined for the last send is gone or has changed (the fork was reverted), forkit clears alto's operation state (`debug_bundler_clearState`) before the next request.
- A successful `eth_getUserOperationReceipt` reply is held until alto has finished with that bundle, so a revert right after a test cannot strand an executor mid-bundle. anvil mines the bundle before alto marks it submitted, so the receipt can arrive first; forkit waits for a final status (`included`, `reverted`, `failed`, `rejected`). An operation still in alto's processing set survives `debug_bundler_clearState` and would block the next deployment of the same account with AA10.

## Deterministic replays

For the fork cache to replay a bundler test offline (see the README), every run must read the same state:

- **Pin the nonce key.** viem's smart accounts default to a nonce key derived from `Date.now()`, which is a new EntryPoint storage slot every run. Pass `nonce: await account.getNonce({ key: 0n })` (or any fixed key).
- **Derive keys from fixed strings**, not `generatePrivateKey()`.
- **Keep the default executor and utility keys**, or pass fixed ones.
- **Build each account afresh in each test.** viem caches that an account is deployed, and a per-test revert undeploys it.

`test/e2e/4337-base.vitest.ts` covers:
- a counterfactual Coinbase Smart Wallet (EntryPoint v0.6);
- a USDC payment with its `Transfer` event;
- an EIP-7702 account (EntryPoint v0.8);
- repeated snapshot/revert rounds.

It replays offline on anvil 1.7.1 and 1.8.3.

## Debugging

- `FORKIT_DEBUG=1` prints alto's output and raises its log level to `info`.
- `b.logs()` returns alto's last lines.
- Boot failures (`BundlerBootError`) include alto's last output.
